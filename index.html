FAQ

Frequently asked questions.

Everything you need to know before we start working together.

Pricing

How much does a project cost?

Every project gets a fixed quote based on its scope, not a vague estimate. After a short call I send a written plan that splits the work into milestones, each with its own price, so you know the full cost before anything starts.

How do payments work?

You pay per milestone, as agreed in the quote. Each milestone ends with working software you can try yourself, so you only pay for progress you have already seen.

Do you also work hourly?

Yes, for ongoing work such as maintenance, small changes or joining your team long term. For a clearly defined project, a fixed quote per milestone is usually simpler for both of us.

Process

How do we get started?

Send a message through the contact form or email me with what you are building and where you need help. I reply with a few questions and a time for a short call, then send a written plan and quote.

How long does a project take?

It depends on the scope, and you will know before we start: every milestone in the quote has its own timeline. Work ships in small steps with working demos, so you see progress along the way instead of waiting for one big reveal.

How will I know how things are going?

You get regular written updates, access to the code as it is written and a working demo at the end of every milestone. If a decision is needed or something changes, you hear about it right away, not at the deadline.

What happens after launch?

I stay available for bug fixes, small changes and the next feature. Many projects continue as ongoing work once the first version is live.

Working together

Do you work with clients outside Nepal?

Yes. I work remotely with clients worldwide and communicate in English over email, chat and video calls. We agree on a regular time for calls that suits your time zone.

Can you work on an existing codebase?

Yes. I start by running your project locally and reading through the code, then make small, tested changes so nothing that already works breaks.

Who owns the code?

You do. The code lives in your repository from the first commit, and you own all of it once the work is paid for.

Tech

What kind of projects do you take on?

Backend work in Java and Spring Boot: new REST APIs, features for an existing Spring app, authentication and payments, microservices with Kafka, and AI features with Spring AI. I focus on the server side and work alongside your frontend developer or team.

Which technologies do you use?

Java and Spring Boot at the core, with Spring Security, Spring Data JPA and Hibernate, PostgreSQL or MySQL for data, Kafka and Redis for messaging and caching, Docker for deployment and Spring AI for LLM features.

Do you write tests and documentation?

Yes. The important paths are covered by automated tests, your frontend team gets API documentation to build against, and the repository includes a README that explains how to run and deploy it.

Still unsure?

Tell me about your project and I will answer anything not covered here.
